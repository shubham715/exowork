EXOWORK / INTEGRATION GUIDE

Connect WhatsApp directly to Meta

Admin updates and employer messages to consenting candidates, using Meta’s hosted WhatsApp Cloud API.

Prepared 2 October 2026 · API default: v26.0 · No Twilio or other messaging provider.

1. What this integration does

  • Admin → Candidates → open a saved candidate profile → Send WhatsApp. The same button is also in the directory.
  • Verified employer → Candidate pool, Interviews, or Selections & joining → Send WhatsApp. The server checks active company membership and an interview-linked application for that company before allowing access.
  • Both roles send from one EXOWORK business number. Employer messages do not originate from each employer’s own phone number. Separate employer WABAs would require another onboarding and credential architecture.
  • Approved templates load directly from the configured WABA. The dialog accepts positional text body variables {{1}}, {{2}}, etc., previews the body, and records acceptance, sent, delivered, read, failed or uncertain status.
  • Only body text templates, optionally with a static text header/footer, are supported. Media, named variables, buttons, carousels, flows and authentication/OTP buttons are excluded from the picker. Create compatible templates as described below.
  • Candidate whatsapp_consent must already be true. Registration captures that choice. Signed incoming STOP, UNSUBSCRIBE, CANCEL or STOP WHATSAPP messages revoke consent. Other replies are acknowledged but not displayed as an inbox.
  • Messages are sent synchronously: no queue worker is required for this feature. There is no bulk campaign sender or automatic status-change notification; admins can manually send approved updates.

Business-initiated updates normally need an approved template. A candidate’s reply opens a 24-hour service window for eligible free-form replies, but this implementation deliberately uses templates for every outbound message. A template send by itself does not open that service window.

2. Create the Meta accounts and test sender

  1. Sign in to Meta Business Suite and create/select the EXOWORK business portfolio. Use business details you can prove, enable administrator two-factor authentication, and retain more than one trusted administrator.
  2. Open Meta for Developers → My Apps → Create App. Choose the business/WhatsApp use case, currently presented as connecting with customers through WhatsApp. Associate the correct business portfolio. Dashboard labels can vary by account.
  3. Open the WhatsApp use case → Customize → API Setup/Quickstart. Meta supplies a test sender, a test WhatsApp Business Account (WABA), and a temporary access token.
  4. Under the test recipient section, add your own WhatsApp number and verify its OTP. Test senders deliver only to Meta’s verified test recipient list; this is separate from EXOWORK candidate consent.
  5. Use Meta’s dashboard to send the default hello_world template to the verified recipient. Copy the Phone Number ID and WhatsApp Business Account ID. These are numeric asset IDs, not a phone number, app ID or portfolio ID.
  6. For production, add a business phone number you control and can verify by SMS/voice. Review Meta’s current migration/coexistence flow if the number already uses WhatsApp or the WhatsApp Business app; do not delete an existing account casually. Configure its display name and complete number registration/two-step verification if the setup flow requests it.
  7. In WhatsApp Manager add the WABA payment method and complete the portfolio/business verification requested for your account. Display-name approval, phone OTP verification, business verification and template approval are different steps.
  8. Check the app’s dashboard requirements and switch to Live mode when ready. An app operating only EXOWORK’s own WABA differs from a platform onboarding other businesses: follow the dashboard’s permission/access-review requirements, and do not assume third-party Tech Provider approval is needed for this single-business integration.

4. Configure signed webhooks

  1. Expose the Laravel public directory through a public HTTPS domain with a valid certificate. A local localhost URL cannot receive Meta callbacks. For local testing, use an HTTPS tunnel pointing to the Laravel server; update the callback if the tunnel URL changes.
  2. In the app’s WhatsApp Configuration/Webhooks section enter https://YOUR-DOMAIN/api/webhooks/whatsapp as the callback and your WHATSAPP_VERIFY_TOKEN as the verification token. Laravel replies with Meta’s challenge after checking the token.
  3. Select the WhatsApp Business Account object and subscribe to messages. This field delivers inbound messages and outbound statuses.
  4. Ensure the app is subscribed to the specific WABA. The dashboard often handles this; if needed, execute the following server-side call using your real IDs and token. Keep the token out of browser URLs and screenshots.
POST https://graph.facebook.com/v26.0/YOUR_WABA_ID/subscribed_apps
Authorization: Bearer YOUR_ACCESS_TOKEN

The POST handler validates X-Hub-Signature-256 against the raw request body and app secret, and accepts only the configured WABA and sender ID. The endpoint is registered in stateless API routes; it does not need a CSRF exception. Leave it publicly reachable, preserving the body and signature header through proxies.

Duplicate/out-of-order receipts are reconciled without rolling read/delivered status back to sent. Receipts arriving before the send response are retained. HTTP acceptance is not delivery; a Meta message ID can later receive a failed status.

Source: Meta Cloud API webhooks.

5. Create, approve and use templates

  1. Open WhatsApp Manager → Message templates for the same WABA used in .env, then Create template.
  2. Choose a category: Utility for specific candidate-requested application/interview updates; Marketing for unsolicited job promotions or broad opportunities. Authentication is for OTPs and is outside this composer’s supported formats. Meta decides the final category; adding promotional content can reclassify a utility template.
  3. Choose a lowercase underscore name, such as exowork_interview_update, and the exact language (for example en, en_US or hi as assigned by Meta). Each translation has its own approval and exact language code.
  4. Choose positional / numbered variables. Use body text with consecutive {{1}}, {{2}}, etc. Avoid media or buttons. A static text header and static footer are optional. Do not place variables only at the beginning/end or make the body mostly variables.
  5. Supply realistic sample values for every variable. Submit for review; check status in Manager. Review may take time and is not guaranteed. Fix a rejected template using Meta’s rejection reason and resubmit or use the available appeal flow. Only APPROVED compatible templates appear in EXOWORK.
  6. Open the candidate’s Send WhatsApp dialog → choose name/language → enter variables in order → review preview → send. A send request rechecks current template approval on Meta; the preview is not editable template text.

Example utility template: exowork_interview_update

Hello {{1}}, your interview for {{2}} with {{3}} is scheduled for {{4}} at {{5}}. This updates the application you submitted to EXOWORK. Reply STOP to stop WhatsApp updates.

Samples: Asha, Machine Operator, Acme Industries, 5 October 2026 at 10:00 IST, Acme Pune office. Send only when the candidate has that application/interview; choosing Utility does not make unrelated messages eligible.

Example marketing template: exowork_job_opportunity

Hello {{1}}, EXOWORK has a new {{2}} opportunity in {{3}}. If you would like details, reply to this message. Reply STOP to stop WhatsApp updates.

Samples: Asha, Warehouse Associate, Pune. Use only for candidates who agreed to relevant job-opportunity messages. The application does not independently track marketing-specific preference categories; confirm the scope of recorded consent before sending promotional templates.

A general “here is an update: {{2}}” template is not a reliable way to send unrestricted text; Meta can reject vague templates. Create specific templates for interview reminders, application status or joining instructions. Variable values must fit the approved purpose.

6. Test safely, then launch

  1. Start with the Meta test sender and your verified test recipient. Register a real candidate record using that number and explicitly grant WhatsApp consent.
  2. Sign in as an active admin with candidate view/update permissions. Open Admin → Candidates; real saved profiles replace the previous demo list. Select the candidate and click Send WhatsApp.
  3. Confirm that configuration is ready and hello_world appears with its exact approved language. It normally has no variables. Send once and check the actual phone.
  4. Observe accepted → sent → delivered/read in Recent messages using Refresh status. A read receipt depends on WhatsApp receipt availability; do not treat missing read status as failure.
  5. Reply STOP from the recipient. Refresh the dialog; consent should be revoked and subsequent sending blocked. Do not silently restore consent. Obtain a fresh explicit opt-in through the candidate profile/registration workflow before restoring it.
  6. For employer testing, verify the employer, attach a candidate application to one of its jobs, and have operations schedule an interview. The button appears in released records. Another employer must be unable to access/send to that candidate unless independently released to it.
  7. Switch to production sender/WABA/token, add billing, approve your actual templates, change callback to the stable production HTTPS URL, refresh config and test one opted-in recipient before wider use.

After a timeout the status is “unknown” and there is no automatic retry. “Check original submission” in the same dialog uses its original request ID and cannot intentionally create another record. Check Meta’s logs before a fresh send; Meta does not provide a general idempotency guarantee for repeated message POSTs. Do not refresh the page and blindly send again.

7. Limits, quality and consent

LimitHow to operate
24-hour customer service windowCount from the candidate’s latest inbound message. Outside it, use an approved template. This integration uses templates even inside the window.
Business-initiated audience limitCheck your current portfolio/account limit in WhatsApp Manager. It concerns unique recipients in a rolling period and is different from messages per second. Verification, usage and quality affect eligibility; do not assume a fixed “1,000/day” for every account.
Sender throughputMeta controls actual sender throughput and upgrade eligibility. This app is a manual sender with at most 10 POST attempts per authenticated user per minute, and a six-second gap per recipient. It is not a bulk dispatcher designed to consume maximum API throughput.
Template quality / pacingApproved templates can later be paused or disabled. Blocks, reports and poor engagement affect quality. Meta may pace, hold, restrict or decline marketing delivery, including recipient/market-specific restrictions.
VariablesThis composer supports up to 20 numbered body variables, each up to 1,024 characters without newline/tab. Meta may impose additional format/content limits. Body content is exactly the approved template plus variables.
Opt-outHonor every withdrawal, including non-keyword requests received by your support staff. Automatic keyword handling is supplementary; an opt-out is not limited to saying STOP. Do not buy lists or infer WhatsApp opt-in from having a mobile number.

For larger campaigns add a separately designed queue, sender-wide throttling, scheduling, purpose-specific consent and billing safeguards. Reuse the authorization, consent and provider service boundaries; do not bypass them.

8. Costs and budgeting

Direct Cloud API avoids a BSP/Twilio subscription or markup; Meta delivery charges still apply. Pricing depends on recipient market, message category, account currency, applicable volume tier and any qualifying free-entry/window rules. Hosting, taxes and advertising charges are separate. Meta’s API acceptance alone is not a billed delivery.

Use the current official developer pricing page and the rate card effective on your sending date, including any October 2026 changes. The public overview and older articles can describe earlier service-message/free-window rules. Full developer pricing pages were rate-limited during preparation, so this guide does not certify current country rates, service allowances or in-window exemptions. Confirm them in your WABA billing screens and effective rate card before budgeting; do not assume all replies or in-window utility templates are free.

  1. Choose the WABA’s billing currency and candidate recipient market (India for Indian numbers). Download the currently effective rate card and volume-tier file from Meta.
  2. Use the final approved category of each template, not the category you initially requested.
  3. Estimate delivered messages by market and category. Apply only exemptions and marginal volume tiers that the current rate card grants to your account. Review any international-authentication rules separately if adding OTPs later.
  4. Compute estimated charge = Σ (billable delivered messages in each market/category/tier × that tier’s unit price) + applicable taxes.
  5. Example arithmetic only: if the live rate were ₹0.12 for a category and you had 10,000 billable deliveries at that tier, the subtotal would be ₹1,200. ₹0.12 is an illustration, not a quoted Meta rate.
  6. Monitor WhatsApp Manager billing/insights and configure any available account spending notifications. EXOWORK does not enforce a rupee budget or display an exact per-send charge.

Official pricing overview: WhatsApp Business Platform Pricing. Always prefer its linked effective developer rate cards for production calculations.

9. Troubleshooting and maintenance

Configuration incomplete / 503Enable WhatsApp, fill all five credential/ID values, use numeric asset IDs, then clear/rebuild Laravel config. All secrets are required so send status can be securely tracked.

131026 / 131049Recipient/delivery issue or Meta delivery/engagement restriction. Consult the exact Meta error documentation. Do not repeatedly retry or switch templates to bypass a restriction.
429 / 130429 / 131056Local request/recipient throttling or Meta sender/pair rate limit. Slow down and review current limits.
Accepted but no delivered statusCheck actual recipient, WABA subscription, messages field, public HTTPS callback, proxy signature preservation, app secret and sender metadata. Successful API submission does not prove delivery.

Official error reference: Meta Cloud API error codes.

Keep the sender credentials scoped and rotate them after exposure. Logs retain candidate/user/company attribution, recipient, template metadata, timestamps and safe error codes; they omit token values, message variables and raw webhook bodies. Define your own retention schedule for whatsapp_messages, whatsapp_receipts and audit logs. Monitor uncertain submissions, failed deliveries, token expiry and template quality. Do not delete message logs merely to defeat duplicate-send protection.

This guide is specific to the EXOWORK integration. Meta interfaces, eligibility, versions and tariffs change. Recheck the linked primary documentation before launch and when upgrading.
